## 1. 주력 과제

**타이틀**  
전사 R&D LIMS 적재를 위한 접착제 레거시 데이터 Parsing Agent 개발

**기간**  
2026.07 ~ 2026.10(목표) · 진행 중

**역할**  
전사 R&D가 실험·시험 데이터를 LIMS(실험실 정보관리 시스템)로 모아 단일 진실원(SSOT)을 구축하려는 전환에서, 접착제 사업부를 선행 적용 도메인으로 두고 작성자·연도마다 제각각인 레거시 엑셀·PPT를 LIMS에 적재 가능한 정규화 데이터로 바꾸는 Parsing Agent 개발을 공동 담당했다. 병목은 LIMS 화면이 아니라 이미 쌓인 비표준 파일이었고, 표준 스키마를 먼저 확정해 모든 파일을 끼워 맞추는 방식 대신, 에이전트가 시트 구조를 해석하며 스키마를 데이터와 함께 다듬는 방향으로 설계·구현에 참여했다. 최종 목적은 파서 제품 자체보다, 접착제부터 적재해 전사로 확대할 수 있는 데이터 입구를 만드는 일이었다.역할은 크게 세 축이다. 첫째, Unipars docgraph 파이프라인이다. ingest 단계에서 원본의 셀·수식·병합·숨김을 SQLite 스테이징 DB에 해석 없이 전개하고, G1 라운드트립으로 재구성 결과가 blob 원본과 일치하는지 검증했다. parse 단계에서는 시트마다 에이전트가 claim(셀 주소를 가리키는 의미 주장)만 남기게 하고, 숫자·단위 값은 모델이 타이핑하지 못하도록 가드레일을 두어 항상 셀 JSON에서 복사되게 했다. lims 단계에서는 오케스트레이터 코드가 claim을 접착제 LIMS V0 29개 테이블(기준정보·조성·공정·측정) 행으로 투영해, 증거 DB(docgraph)와 제품 DB(LIMS sqlite)를 분리했다. recipe·sample·measurement_result처럼 행의 의미 단위(grain)를 섞지 않도록 스키마 제약을 코드와 문서에 맞췄고, 기존 Control Tower·제품군별 하드코드 어댑터·이중 저장소 경로를 제거해 ingest→parse→lims 단일 제품 경로로 리뉴얼하는 작업에도 참여했다.둘째, 글로벌 스키마(공책)와의 공진화다. 파일마다 다른 스키마나 매니페스트 중간층을 두지 않고, adhesive-lims-schema 루트 스키마에 에이전트가 파일 단위 적재 실험(analyses)을 직접 커밋하는 방식을 따랐다. MI-data 파트와 역할을 나눠 Explorer로 적재 결과를 검수·합격시키고, 사람만 아는 의미는 질문 문서로, 스키마가 못 받는 사실은 schema-feedback으로 남겨 표 구조를 함께 키웠다. Track A(데이터 기반 Parsing Agent)로서 Track B(Human 스키마 보완)와 경계를 유지하면서도 접착제 도메인 숙지에 함께 참여해, 파싱 결과가 연구원이 승인할 수 있는 근거와 최소 질문만 남기도록 품질 기준을 맞췄다.셋째, 제품화·품질 기준이다. frontend·backend·worker를 서버리스로 나누고 업로드·작업 ID·checkpoint를 외부 저장소에 두는 제품 제약을 PoC와 정렬했으며, file-analysis harness의 source ledger 1:1 대조·residue 전수 회계·silent miss 0% 같은 무결 적재 검증을 품질 기준으로 삼아 조용한 오파싱을 막는 쪽을 우선했다. 본인은 Unipars docgraph 리뉴얼과 sqlite 스키마·식별자(문서·시트·셀 SHA-256) 정리, LIMS 투영 경로 문서화를 맡아 재현 가능한 배치 CLI(uv run) 기준으로 공유했다. 또한 원본 파일은 Git에 올리지 않고 취합 저장소와 분리하며, 스테이징·카탈로그·LIMS sqlite의 역할을 문서와 ADR로 구분해 팀이 같은 용어로 협업하게 정리했다. 이를 통해 파서가 “그럴듯한 표”를 만드는 도구가 아니라, 전사 데이터 거버넌스의 첫 관문으로서 추적 가능하고 검수 가능한 적재 경로를 제공하도록 역할을 정의했다. 목표 완성 시점은 2026년 10월 이전이며, 접착제 선행 적재 후 전사 확대를 염두에 두고 일했다. 요약하면, 비표준 연구 데이터를 전사 LIMS SSOT로 흘려보내기 위한 에이전트 파싱, 스키마 공진화, 검증 가능한 적재 파이프라인을 실무에서 설계하고 구현·운영한 역할이다 전사 확대 시에도 동일 파이프라인이 재사용될 수 있도록 도메인 특화 하드코딩을 최소화했다.
