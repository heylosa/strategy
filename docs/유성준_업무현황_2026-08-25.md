#### 왜 하는가 (목적성)

전사 R&D는 실험·시험 데이터를 **LIMS(Laboratory Information Management System)** 로 모아 **단일 진실원(SSOT)** 을 세우려 한다. 연계 프로젝트 [전사 R&D LIMS 도입](https://wiki.sofabudget.com/doc/rd-lims-gnVFBBXfMd)의 전략은 **접착제 사업부를 먼저 넣고, 이후 전사로 확대**하는 것이다.

병목은 LIMS 화면이 아니라 **이미 쌓인 레거시 파일**이다. 작성자·연도마다 엑셀(·PPT) 서식이 달라, 사람이 파일마다 손으로 맞추면 전사 적재가 막힌다. 이 프로젝트는 그 앞단을 맡는다.

```text
연구원 레거시 Excel·PPT (제각각 서식)
        │
        ▼
[이 프로젝트] 포맷 해석 · 파싱 · 정규화 (canonical / LIMS 스키마 행)
        │
        ▼
전사 R&D LIMS 적재 (API/import · 제품 확정 후)  ← SSOT, 접착제 先行 → 전사 확대
        │
        ▼
조회 · 이력 · 권한 · 리포트 · (이후 AX·Agent 활용)
```

설계 방향([설계 컨셉 2026-07-27](https://wiki.sofabudget.com/doc/2026-07-27-QUb4qg0rGv)):

- 스키마를 먼저 고정해 파일에 끼워 맞추지 않고, **에이전트가 서식을 해석**하며 스키마를 데이터와 함께 다듬는다.
- 파서가 다듬는 스키마와 LIMS 스키마는 **공진화**한다. 현장 데이터에만 반복되는 항목은 LIMS 쪽이 반영할 신호로 본다.
- 성공은 모델 성능만이 아니라, 연구원이 **최소 질문 + 근거 있는 매핑**으로 승인할 수 있는 흐름까지 포함한다.

투트랙([2026-07-23](https://wiki.sofabudget.com/doc/parser-2026-07-23-EoJ1vgqseO)): **Track A**(유성준·백종근) = Data 기반 Parsing Agent, **Track B**(김수진·이준영) = Human 스키마·수동 보완.

#### 기술 스택 · 저장소 구조 (2026-08 기준)

목적이 LIMS 적재이므로, 스택도 **“증거(원본 셀)”** 와 **“제품(LIMS 행)”** 을 분리한다.

| 층 | 무엇인가 | 기술·산출 |
|----|----------|-----------|
| **원본** | 연구원 엑셀·PPT | Teams/OneDrive 취합. **Git에 원본 커밋 금지** |
| **증거 DB (docgraph)** | 셀·수식·병합을 해석 없이 펼친 뒤, 에이전트 claim으로 의미 주장 | **Unipars** `src/unipars/docgraph/` · 스테이징 **SQLite** · DDL `schema.sql` |
| **제품 DB (LIMS V0)** | 처방·원료·공정·시료·시험·측정 등 **29테이블** 정규화 모델 | `lims-schema-v0.sql` · 파일별 `analyses/<file-id>/sqlite/lims.sqlite` |
| **글로벌 스키마 공책** | 모든 파일이 같이 쓰는 표 구조(중간 어댑터/매니페스트 없이 직접 INSERT) | 리포 **`adhesive-lims-schema`** (`schema.sql`, Explorer, `file-analysis` 하네스) |
| **에이전트 런타임** | 시트 단위 해석 · claim만 생성(숫자는 셀에서 복사) | Frontier/코딩 에이전트 · Skills · (라이브) GCP Vertex / 테스트 시 TestModel |
| **오케스트레이션** | DB 쓰기는 모델이 아니라 코드 | `pipeline.py` · `project.py` · 출력 가드레일(모델 typed value 금지) |
| **검증·탐색** | LIMS 없이도 파서 품질 확인 · 적재 결과 열람 | Golden fixture · G1 라운드트립 · Explorer(읽기 전용) · `browse` (`127.0.0.1:8765`) |
| **패키징·CLI** | 배치 파이프라인 실행 | **`uv run python -m unipars.docgraph`** (`ingest` / `parse` / `lims`) |

**Unipars 라이브 제품 경로** (2026-08-25 ADR-0001 이후 — Control Tower·Observer Lab·패밀리 어댑터 경로는 폐기):

```text
ingest (코드만, G1)  →  parse (시트마다 에이전트, claim=셀 주소)  →  lims (오케스트레이터 → 29 LIMS 테이블)
         │                        │
         └─ 스테이징 sqlite        └─ load/verify 는 디버그(카테고리 그래프). 제품 질문의 권위는 lims.sqlite
```

docgraph 층: **raw**(document/sheet/cell…) → **reasoning**(reading/claim) → (디버그) taxonomy/graph/verdict. claim·assertion에 **값 컬럼 없음** — `numeric_value` 등은 셀 JSON에서 오케스트레이터가 복사.

**접착제 LIMS 스키마 V0** ([해설 2026-08-24](https://wiki.sofabudget.com/doc/lims-v0-2026-08-24-RmMIhin5FQ)): 기준정보 17 + 조성 5 + 공정 2 + 측정 5 = **29테이블**. `recipe` / `sample` / `measurement_result` grain을 섞지 않음. 셀 좌표·SHA256 원장은 파서 쪽, 단가·BOM은 비범위.

**글로벌 스키마 협업** ([가이드 2026-08-25](https://wiki.sofabudget.com/doc/2026-08-25-TwtykL7Bov)): 파일마다 다른 스키마·매니페스트 어댑터를 두지 않고, 에이전트가 **루트 공책에 바로 적재 실험**. MI-agent(유성준·백종근 포함)가 `analyses/<file-id>/` 실험 커밋 → MI-data가 Explorer 합격·질문 답변 → 빈칸은 `schema-feedback` → 공책 버전업.

**제품화 PoC 쪽 제약** ([8/21 계획](https://wiki.sofabudget.com/doc/poc-8-21-2026-08-11-Qg6xakZIgt)): `frontend` · `backend` · `worker`를 **서버리스**로 분리, 상태·checkpoint는 외부 저장소, 모노리포·System Handbook·ADR. 연습장: `pydantic-ai-playground`, `claude-agent-sdk-playground`, `adhesive-parser-experiment`(file-analysis harness · source ledger 1:1 · silent miss 0%).

**본인(유성준)이 남긴 기술 산출물 예:** [Unipars docgraph 리뉴얼](https://wiki.sofabudget.com/doc/unipars-docgraph-2026-08-20-XjLmm7eX8Q) · [Unipars sqlite 스키마](https://wiki.sofabudget.com/doc/unipars-sqlite-2026-08-25-hDm4Dgv6yT) · 리모트 예 `unipars-ysj`, `Sangwon/adhesive-lims-schema`.
