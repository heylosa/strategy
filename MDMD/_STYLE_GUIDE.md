# MDMD 학습자료 작성 규약 (Style Guide)

이 폴더의 모든 `md/*.md` 파일은 아래 규약을 따른다. 규약을 지켜야 `build.py`가 Typst(`typst/chapters/*.typ`)와 PDF로 손실 없이 변환한다.

## 1. 대상 독자와 목적

- 대상: SK hynix **Tech R&D - Product Engineering(PE)** 지원자. A!SK(AI 영상 인터뷰, 직무지식 문항: 1분 준비 후 30초~3분 구술 답변) 및 실무 심화 학습.
- 목적: **기초 → 개념 → 응용 → 심화 → 질문지**를 1주일 안에 하드코어로 학습. 양 제한 없음.
- 관점: 공정을 "만드는 사람"이 아니라 **제품(DRAM/NAND/HBM)의 특성·수율·신뢰성을 책임지는 PE** 관점. 즉 "이 공정 변수가 흔들리면 제품의 어떤 전기적 특성/불량/수율로 나타나는가, 그걸 어떻게 잡아내고(분석) 어떻게 풀어내는가(트러블슈팅)"가 항상 중심.

## 2. 각 챕터의 공통 골격

모든 챕터(00, 21, 22 제외)는 아래 9개 절을 순서대로 포함한다. 절 제목은 자유롭게 구체화해도 되지만 순서와 취지는 유지.

1. `## 1. 한눈에 보기` — 왜 PE에게 중요한가(5줄), 핵심 키워드 10~15개(표: 용어 | 한 줄 정의).
2. `## 2. 기초` — 아무것도 모르는 사람이 읽어도 되도록 물리/화학/전기 기초부터. 반드시 **구체적 숫자와 예시** 포함.
3. `## 3. 공정/기술 상세` — 종류별 비교표, 장비 구성, 핵심 공정 변수 표(변수 | 조절 방향 | 영향 받는 결과 | 모니터링 항목/계측).
4. `## 4. 결함·불량 유형` — 표(결함명 | 현상 | 발생 원인 | 검출/분석 방법 | 대책). 가능한 모든 유형을 망라.
5. `## 5. 공정 변수 ↔ 소자/제품 특성 상관관계` — 변수 shift → 전기적 특성 변화(Vt, Ioff, Ion, 누설, retention, tWR, tRCD, program/erase 속도, endurance, RC delay 등) → 수율/신뢰성 영향. DRAM/NAND 각각.
6. `## 6. 트러블슈팅 케이스` — 케이스 3개 이상. 각 케이스는 `증상 → 1차 데이터(어떤 계측/맵/전기 데이터) → 가설 나열 → 가설 검증 방법 → 근본 원인 → 조치 → 재발 방지`. 해결이 어려운 현안은 `> **[아이디어]**` 박스로 미해결 아이디어를 제시.
7. `## 7. 응용·심화(최신 이슈)` — 현업/최신 기술 이슈(EUV, HAR etch, 3D DRAM, HBM4, hybrid bonding, 1c nm DRAM, 300+단 NAND 등).
8. `## 8. 셀프 체크 질문` — 개념 5 / 응용 5 / 심화 5 (총 15개 이상). 각 질문 아래 `- 답:` 으로 3~6줄 모범 답안. A!SK 구술 답변을 염두에 두고 "결론 → 근거 → 예시" 순.
9. `## 9. 한 페이지 요약` — 표 또는 리스트로 이 챕터의 핵심을 한 페이지에.

## 3. 글쓰기 원칙

- 한국어. 전문 용어는 첫 등장 시 `한글(English)` 표기, 이후 자유.
- 문장은 짧게. 한 단락 5줄 이내. 개념 → 예시 → 왜 중요한가 순서.
- **모든 개념에 구체적 숫자 예시**를 붙인다. (예: "산화막 두께 2 nm → EOT 1.2 nm 수준", "Dose ±2% 변동 → CD 약 ±1 nm 변동").
- 값이 회사/세대마다 다르면 "대략", "일반적으로", "예시 값" 명시. 확실치 않은 숫자는 범위로 쓴다.
- 모든 불량/결함은 반드시 **원인 → 검출 → 대책** 3요소를 채운다.
- 비유는 1개까지만, 그 뒤 반드시 기술적 설명으로 연결.
- 이모지 사용 금지(PDF 폰트 문제).

## 4. 콜아웃 박스 (blockquote)

첫 줄에 라벨을 굵게 쓰고 그 아래 내용을 쓴다. 라벨은 아래 7종만 사용.

```
> **[핵심]** 한 줄 요약도 가능
> 여러 줄이면 계속 `> `로 이어서 쓴다.
```

- `[핵심]` 꼭 외워야 할 것
- `[예시]` 구체 숫자/상황 예시
- `[트러블슈팅]` 증상→원인→조치 미니 케이스
- `[아이디어]` 미해결 문제에 대한 개선 아이디어
- `[면접]` A!SK/면접에서 이렇게 답하라 (30초~1분 분량 구술 스크립트)
- `[주의]` 흔한 오해/함정
- `[심화]` 대학원/현업 수준 보충

## 5. 허용 Markdown 문법 (변환기 호환)

- 제목: `#`(챕터 제목, 파일당 1개, 첫 줄) / `##` / `###` / `####`
- 단락: 빈 줄로 구분. 단락 안 줄바꿈은 공백으로 합쳐진다.
- 강조: `**굵게**`, `*기울임*`(밑줄 `_` 기울임 금지), `` `인라인 코드` ``
- 목록: `- 항목`, `1. 항목`. 중첩은 2칸 들여쓰기. 목록 항목 안에 표/코드블록 넣지 않기.
- 표: GFM 파이프 표. 헤더 행 + 구분 행(`|---|---|`) 필수. 셀 안에 줄바꿈 금지, 셀 안에 `|` 금지. 열은 6개 이하.
- 코드/ASCII 도식: ```` ```text ```` 펜스 블록. 80칸 이내, ASCII 문자(`+ - | / \ < > ^ v`)만 사용.
- 수식: LaTeX(`$`) 금지. 유니코드 평문으로 쓴다. 예: `I_D = μ_n·C_ox·(W/L)·(V_GS − V_th)²`, `τ = R·C`, `Δ`, `≈`, `≤`, `≥`, `→`, `×`, `√`, `Ω`, `°C`.
- 수평선: `---` 단독 줄.
- 금지: HTML 태그, 이미지, 각주, 링크 문법(참고문헌은 평문으로), 체크박스, 정의 목록, 취소선.

## 6. 파일 규칙

- 파일명: `NN_주제.md` (NN 두 자리). 첫 줄은 `# NN. 챕터 제목`.
- 분량: 챕터당 600~1200줄 이상 권장(표·예시 포함). 하드코어 학습용이므로 길어도 좋다. 단, 중복·군말 없이.
- 인코딩 UTF-8, 줄바꿈 LF.
