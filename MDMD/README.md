# MDMD: 반도체 메모리 Product Engineering 학습 교재

## 이 자료는 무엇인가

SK hynix Tech R&D - Product Engineering(PE) 직무 지원자를 위한 1주일 하드코어 학습 교재다. A!SK(AI 영상 인터뷰) 직무지식 문항 대비와, 입사 이후 실무 심화 학습을 하나의 자료로 묶었다.

공정을 "만드는 사람"의 시선이 아니라, 제품(DRAM/NAND/HBM)의 전기적 특성·수율·신뢰성을 책임지는 PE의 시선으로 쓴다. 모든 장의 중심 질문은 같다. "이 공정 변수가 흔들리면 제품의 어떤 특성·불량·수율로 나타나는가, 그것을 어떤 데이터로 잡아내고 어떻게 풀어내는가."

## 대상

- SK hynix Tech R&D PE 직무 지원자(학사·석사 신입, 경력 전환 포함)
- A!SK 직무지식 파트(준비 약 1분, 답변 30초~3분 구술)를 앞둔 사람
- 공정·소자 배경은 있으나 제품 관점(EDS, 비트맵, tail, 신뢰성, PCN)이 약한 사람
- 반도체 기초가 없어도 01장부터 순서대로 읽으면 따라올 수 있도록 기초부터 쓴다

## 폴더 구조

```text
MDMD/
  README.md            이 문서
  _STYLE_GUIDE.md      작성 규약 (모든 md 파일이 따라야 함)
  build.py             md -> Typst -> PDF 빌드 스크립트
  md/                  원고 (00_학습가이드.md ~ 22_1주_치트시트.md)
  typst/
    template.typ       한글 본문/표/콜아웃 템플릿
    main.typ           build.py가 생성하는 합본
    chapters/          챕터별 .typ (생성물)
  pdf/
    MDMD_PE_ASK_Study.pdf
    MDMD_PE_ASK_Compact.pdf   약 30페이지 급행본
  compact/                 초심자용 압축본 (원본은 compact/md/)
    md/00_컴팩트.md
    build.py               python compact/build.py
```

- 본편 원본은 `md/`, 급행 원본은 `compact/md/`이다. `typst/`와 `pdf/`는 빌드 산출물이므로 직접 편집하지 않는다.
- 파일명은 `NN_주제.md` 형식이고 첫 줄은 `# NN. 챕터 제목`이다.

## 1주일 사용법

하루 10~12시간 기준. 자세한 일정과 하루의 틀은 `md/00_학습가이드.md` 4절에 있다.

| 일차 | 장 | 산출물 |
|---|---|---|
| Day 1 | 01, 02 | DRAM/NAND 비교표 백지 재현 |
| Day 2 | 03, 04, 05 | 공정 변수 → 제품 특성 화살표 20개 |
| Day 3 | 06, 07, 08 | "식각 프로파일 붕괴 시 NAND 영향" 1분 답변 녹음 |
| Day 4 | 09, 10, 11 | 웨이퍼 맵 시그니처 8종과 공정 후보 연결 |
| Day 5 | 12, 13, 14 | 불량 모드 카드 30장 |
| Day 6 | 15, 16, 17, 18 | 아이디어 박스 10개 재서술 |
| Day 7 | 19, 20, 21, 22 | 카메라 앞 모의 7문항, 한 줄 정의집 |

읽는 원칙 세 가지.

- 매 장의 셀프 체크 문항을 소리 내어 60초 안에 답한다. 읽은 양이 아니라 입으로 나온 문항 수가 준비도다.
- 모든 개념을 변수-계측-소자/제품-조치 네 칸으로 다시 적는다. 빈 칸이 약점이다.
- DRAM과 NAND를 항상 한 쌍으로 묻는다. 같은 공정 이슈라도 두 제품에서 죽는 특성이 다르다.

시간이 부족하면 각 장의 5절(변수 ↔ 특성 상관)과 8절(셀프 체크)만 읽어도 A!SK 답변 골격은 채워진다.

## PDF 빌드 방법

요구 사항: Python 3.12+, `pip install typst`(컴파일러 바인딩), Windows면 맑은 고딕(`C:\Windows\Fonts\malgun.ttf`).

```text
cd MDMD
python build.py
```

`build.py`는 `md/*.md`를 읽어 `typst/chapters/*.typ`와 `typst/main.typ`으로 변환한 뒤 PDF를 `pdf/MDMD_PE_ASK_Study.pdf`에 쓴다. Typst만 변환하고 PDF는 나중에 만들려면 `python build.py --no-pdf`. 변환이 손실 없이 되려면 원고가 `_STYLE_GUIDE.md`의 허용 문법 안에 있어야 한다. 빌드 오류가 나면 대개 표 열 수 초과, 셀 안 줄바꿈, 허용되지 않은 콜아웃 라벨, LaTeX 수식 중 하나다. 1주일 플랜의 상세는 `md/00_학습가이드.md`를 본다.

급행(약 30페이지, 기초 0 기준)은 본편과 별도다.

```text
cd MDMD
python compact/build.py
```

산출물은 `pdf/MDMD_PE_ASK_Compact.pdf`. 원고는 `compact/md/00_컴팩트.md`. 본편 `md/`는 건드리지 않는다.

## 규약 요약

전체 규약은 `_STYLE_GUIDE.md`에 있다. 원고를 쓰거나 고칠 때 최소한 아래를 지킨다.

- 한국어로 쓴다. 전문 용어는 첫 등장 시 `한글(English)`로 쓴다.
- 문장은 짧게, 단락은 5줄 이내. 개념 → 예시 → 왜 중요한가 순서.
- 모든 개념에 구체적 숫자 예시를 붙인다. 세대마다 다른 값은 "대략", 범위로 쓴다.
- 모든 불량·결함은 원인 → 검출 → 대책 3요소를 채운다.
- 이모지를 쓰지 않는다. PDF 글꼴 문제가 생긴다.
- 콜아웃은 blockquote 첫 줄에 굵은 라벨 7종만 쓴다. `[핵심]`, `[예시]`, `[트러블슈팅]`, `[아이디어]`, `[면접]`, `[주의]`, `[심화]`.
- 제목은 `#`(파일당 1개, 첫 줄) / `##` / `###` / `####`만 쓴다.
- 표는 GFM 파이프 표, 헤더와 구분 행 필수, 열 6개 이하, 셀 안 줄바꿈과 `|` 금지.
- 코드·ASCII 도식은 ```` ```text ```` 펜스, 80칸 이내, ASCII 문자만.
- 수식은 LaTeX 대신 유니코드 평문으로 쓴다. 예: `τ = R·C`, `ΔV = V·Cs/(Cs+C_BL)`.
- HTML, 이미지, 각주, 링크 문법, 체크박스, 정의 목록, 취소선을 쓰지 않는다.
- 파일은 UTF-8, 줄바꿈 LF. 분량은 챕터당 600~1200줄 이상 권장.
